<Lead>
  Direct sharing works for one-off files. For a folder shared with a family, a team, or a
  research group, you want something that scales past pairwise encryption.
</Lead>

## The group-key model

A naive encrypted file-sharing app wraps every file to every recipient's public key. Ten members
means ten copies of each content key. An eleventh person joining means re-encrypting everything.

Opake uses **workspaces** instead — a named group that owns a single shared symmetric key (the
"group key"). Files in the workspace have their content keys wrapped under the group key, not
directly under each member's key.

1. The file's content key is wrapped once under the group key.
2. The group key is wrapped once per member, under each member's X25519 public key.

Adding a member means wrapping the group key for them once. They immediately gain access to
every file ever uploaded under that workspace — no re-encryption of the files themselves.

---

## 1. Creating a workspace

A workspace is a single record on the AT Protocol (`app.opake.keyring`).

<PlatformToggle>
  <PlatformTab name="Web App">

    1. Click the **(+)** icon in the Sidebar and select **New Workspace**.
    2. Give it a name (e.g., "Family Photos").
    3. Opake generates a group key, wraps it to your public key, and publishes the record.

  </PlatformTab>
  <PlatformTab name="CLI">
    <CodeBlock language="sh">opake workspace create "Family Photos"</CodeBlock>
  </PlatformTab>
</PlatformToggle>

## 2. Managing membership

### Adding a member

Adding someone means wrapping the current group key to their public key and updating the
workspace record. They can then decrypt anything stored under that workspace.

### Removing a member (key rotation)

When you remove a member, Opake rotates the group key so the removed member can't decrypt
files uploaded after their removal:

1. Generate a new group key.
2. Wrap it to all remaining members.
3. Archive the previous group key into the workspace's key history so remaining members can
   still decrypt files uploaded under older rotations.

<Callout type="warning">
  Key rotation prevents the removed member from decrypting _future_ files. Anything they already
  downloaded and decrypted locally is theirs — rotation can't reach across the network to
  delete copies.
</Callout>

---

## 3. Uploading to a workspace

<CodeBlock language="sh">opake upload "budget.pdf" --workspace "Family Photos"</CodeBlock>

Every member of that workspace sees the file in their directory tree and can decrypt it
without extra steps.
